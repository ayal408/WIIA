# שרת מעקב תמונות — אילי מייל

זה קוד שרת אישי, לא שירות פעיל. לא בוצעה פריסה, ואין כתובת ציבורית מוכנה. נדרש אירוח HTTPS נגיש גם לתוסף וגם לשרתי הדואר של הנמענים. localhost מתאים לבדיקת API בלבד; נמענים אינם יכולים לטעון ממנו תמונות.

## מה נמדד

השרת סופר בקשות GET לתמונת GIF ייחודית רק לאחר הפעלה מפורשת. בקשת HEAD אינה נספרת. הספירה אינה מוכיחה קריאה אנושית: סורקי אבטחה, טעינה מראש, צפייה של השולח, חסימת תמונות ומטמונים יכולים לעוות אותה. אין זיהוי של אדם מסוים בריבוי נמענים ואין ניסיון לזהות כתובת IP או מיקום.

## הרצה ב־Docker

1. העתיקו `.env.example` לקובץ `.env` מקומי. הגדירו כתובת HTTPS אמיתית ומפתח חדש. אפשר ליצור מפתח עם `python -c "import secrets; print(secrets.token_urlsafe(32))"`. אין לשמור מפתח אמיתי ב־Git.
2. מתוך תיקיית `ili-mail-tracker` הריצו:

```bash
docker build -t ili-mail-tracker .
docker volume create ili-mail-tracker-data
docker run --name ili-mail-tracker --env-file .env -p 127.0.0.1:8080:8080 -v ili-mail-tracker-data:/data ili-mail-tracker
```

3. העמידו reverse proxy עם TLS לפני פורט 8080, והפנו את הדומיין שהוגדר ב־PUBLIC_BASE_URL. ודאו שה־volume ניתן לכתיבה למשתמש tracker שבמכולה. אל תמחקו את ה־volume בשדרוג.
4. פתחו בתוסף ״מעקב פתיחה״, הזינו את כתובת השרת והמפתח, ואשרו גישה לדומיין הזה בלבד.

המכולה משתמשת ב־Gunicorn עם תהליך יחיד וארבעה threads וב־SQLite. בניית Docker ופריסה ב־Gunicorn לא נבדקו בסביבה זו. בדיקות השרת משתמשות ב־WSGI ובשרת HTTP מקומי זמני.

## שימוש לכל הודעה

1. בחרו במפורש מעקב להודעה וצרו פריט. התווית נשמרת במחשב בלבד; לשרת לא נשלחים נמען, כותרת או גוף ההודעה.
2. לחצו ״העתקת תמונת המעקב״ והדביקו בגוף המייל ב־Gmail. זה HTML של תמונת 1×1; יש לבדוק שהעורך אכן שומר אותה בהודעה. אין צירוף אוטומטי.
3. שלחו את המייל ידנית ב־Gmail.
4. לחצו ״שלחתי — הפעלת מעקב״. רק מרגע זה GET לתמונה נספר. פתיחה מוקדמת לא תיספר.
5. ״בדיקת מצב״ קורא את הספירה מהשרת. אין polling או התראות אוטומטיות. השהיה עוצרת את הספירה; מחיקה מסירה את הרשומה.

צפייה במייל שנשלח, העתקה מחדש או טעינת התמונה של השולח לאחר ההפעלה יכולה להיספר גם היא. נתון ״פעיל״ אינו אישור מסירה.

## API ופרטיות

- `POST /api/tracks` דורש Bearer עם מפתח היצירה ומחזיר מזהה אקראי, קישור תמונה ואסימון ניהול נפרד.
- `GET /api/tracks/{id}`, `POST .../arm`, `POST .../disable`, `DELETE ...` דורשים את אסימון הניהול של אותו פריט. מפתח היצירה אינו פותח נתוני פריט.
- `GET /p/{id}.gif` אינו דורש התחברות. פריט חסר, מושהה או שפג תוקפו מחזיר אותה תמונה בלי לספור. אין cookies.
- SQLite שומר מזהה, hash של אסימון ניהול, תוקף, מצב, מספר בקשות וזמני בקשות ראשונה ואחרונה. אינו שומר IP, User-Agent, נמען, כותרת או תוכן מייל.
- השרת וספק האירוח עדיין מקבלים נתוני רשת בעת הבקשה. הגדירו ב־reverse proxy מדיניות logs מתאימה; אין להבטיח אנונימיות רק מפני שהיישום לא שומר IP.
- תוקף ברירת המחדל הוא 30 יום, ניתן להגדיר 1–90. הרשומה מפסיקה לספור מיד בתום התוקף; רשומות שפג תוקפן נמחקות בעת יצירת פריט חדש. ניתן למחוק ידנית קודם.
- קיימת מכסה של 10,000 רשומות. אין כאן מערכת משתמשים ציבורית: מפתח היצירה מיועד לשרת אישי ואינו מתאים לחלוקה לכל משתמשי תוסף ציבורי.

## בדיקות

```bash
python -m unittest discover -s tests -v
```

הבדיקות כוללות הרשאות ניהול, בידוד אסימונים, הפעלה והשהיה, מחיקה, תוקף, HEAD, תצורת HTTPS, ספירה ובדיקת HTTP אמיתית על loopback. Gmail, הדבקת HTML, פרוקסי תמונות ונטפרי דורשים אימות נפרד.
